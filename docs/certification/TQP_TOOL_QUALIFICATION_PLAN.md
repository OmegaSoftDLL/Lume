## 5. Known limits of the evidence

1. `ltv` covers the integer fragment (int/bool parameters, + - * / %, comparisons, and/or, if, let, calls, ctfail). Functions outside it are reported `unsupported`, never `validated`.
2. `ltv` reasons over the integers: its theorem holds for executions without an i64 overflow trap. Runtime helpers (addv, __rt_sub, __rt_mul, __rt_div, __rt_mod, cmpv, eqv, mkint, __rt_cond) are axioms, checked against the real machine by the native boundary run and by the mutation gate, not proven.
3. The Lean 4 certificates are exported but were not machine-checked unless the evidence file says `lean_checked: true`; SMT-LIB2 certificates are checked only when a solver is installed (`external_solver`).
4. `lmcdc` measures coverage of the lowered AST the code generator receives, not of the object code; the link between the two is `ltv`.
5. Channel B of the safety envelope is a software RV32IM interpreter on the same host: design diversity, not physical independence. The front end is common to both channels. Its number domain is i32.
6. The runtime (collector, boxed integers, string and list primitives) and `lasm` are tested and stressed, not formally verified.
7. QUALIFICATION_EVIDENCE.json is hash-chained and signed with Ed25519, but with a developer key that this tool generates and keeps in a file on the host: the signature shows which key holder produced the file, it is not an attestation by an independent party. The soak ledger and the safety-envelope event log are hash-chained, not signed.
8. The AArch64, RV64 and RV32 back ends cover the integer kernel fragment only and were executed on emulators (qemu user mode, the LumePuter interpreter), not on silicon; the bare AArch64 image is validated but not executed.
9. The [C0010] check of `ltv` scans the instructions of the `@secret` function itself. Runtime helpers it reaches by `call` (boxing, bitwise helpers, the promise constructor) are not scanned, so it is not an end-to-end constant-time proof.
10. The cryptography of `lcrypto_tls.src` is tested against the official vectors and against forgeries; it is not formally verified, its constant-time property is by construction at source level, and the TLS 1.3 code is a handshake and record implementation without X.509 path validation.
11. A neural cartridge is evaluated by this tool chain's own integer forward pass; nothing is claimed about a floating-point inference engine that loads the same file.
